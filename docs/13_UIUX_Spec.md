# 第十三部分 原型与 UIUX

## 1. 信息架构

```text
策略工作台
  -> 理解与澄清
  -> 策略确认
  -> 执行进度
  -> 筛选结果
       -> 条件矩阵
       -> 证据抽屉
       -> 研究增强（P1）
  -> 自然语言修改与版本对比
```

## 2. 页面规格

| 页面 | 用户目标 | 核心组件 | 主要动作 |
| --- | --- | --- | --- |
| 策略工作台 | 说出想法 | 输入区、示例、边界提示 | 提交、选择示例 |
| 理解与澄清 | 检查系统是否理解 | Universe 卡片、条件草稿、澄清项 | 选实体、编辑建议 |
| 策略确认 | 决定是否执行 | 条件列表、版本、数据口径、确认按钮 | 确认、返回修改 |
| 执行 | 感知处理过程 | 分步进度、运行版本、重试 | 等待、取消、重试 |
| 结果页 | 判断匹配和原因 | 漏斗、矩阵、状态图例、策略摘要 | 展开证据、筛选状态 |
| 证据抽屉 | 核验一项结论 | 原值、计算值、公式、来源、时点、口径 | 关闭、复制引用 |
| 修改面板 | 迭代策略 | 输入框、Patch diff、影响提示 | 预览、确认、取消 |

## 3. 关键交互

### 3.1 澄清是批量、可编辑的

面对“利润增长较快、估值不要太高、走势稳定”，页面同时显示三个建议口径和阈值。每项都带 `建议` 状态，用户可以直接改数字或删除条件。任何未解决的歧义都让执行按钮保持禁用并写明原因。

### 3.2 确认是不可省略的

确认区展示策略版本、Universe、每个条件、时间口径和数据来源。点击“确认并执行”后生成不可变版本号；返回编辑创建新草稿，不能覆写已执行版本。

### 3.3 结果矩阵优先于单一推荐列表

每个条件都显示 `PASS`、`FAIL` 或 `UNKNOWN`，Unknown 用文字和图标说明原因，不能只用灰色。结果行可展开；证据抽屉必须展示具体规则，例如 `18.7x < 25x -> PASS`。

### 3.4 Patch 先预览再生效

输入“PE 改成 20”后，面板只显示一处修改：`PE-TTM < 25x -> PE-TTM < 20x`，其他条件列为“保持不变”。点击确认才生成 v2，并重新执行。

## 4. 视觉层级

- 页面基调：安静、信息密集、接近研究工作台，不做聊天气泡主导或夸张金融行情装饰。
- 主标题 24px，页面内面板标题 16px，正文 14px，数据辅助文字 12px；字距为 0。
- 使用中性浅背景、白色内容面、深色正文；强调色只用于明确动作和选中态。
- 状态配色同时配合文本和图标：PASS 为绿色、FAIL 为红色、UNKNOWN 为金色、TOOL_ERROR 为橙红色、STALE 为紫灰色。
- “演示数据”必须固定在策略摘要旁，不应藏在页脚。
- 证据和错误都采用展开面板或抽屉，不堆叠卡片套卡片。

## 5. 空、加载与异常状态

| 状态 | 页面表现 | 用户下一步 |
| --- | --- | --- |
| 空输入 | 输入提示和示例 | 选择示例或输入策略 |
| 解析中 | 不可跳动的分步状态 | 等待或取消 |
| 实体歧义 | 候选列表和差异信息 | 选择一个 Universe |
| 零结果 | 漏斗、最强约束和原策略 | 修改条件，不自动放宽 |
| Unknown | 条件格显示缺失原因 | 查看证据或暂时排除 |
| Tool Error | 可读错误和重试按钮 | 重试或返回策略 |
| Stale | 时点和过期提示 | 切换 as_of 或等待更新 |

## 6. Demo 对应关系

`demo/index.html` 用一个单页原型演示上述关键页面的压缩版：输入、解析、确认、结果矩阵、证据抽屉和 Patch 预览。它的演示数据标签和合规边界是产品交互的一部分。
