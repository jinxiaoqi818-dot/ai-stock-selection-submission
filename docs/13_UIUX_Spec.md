# 第十三部分 原型与 UIUX：方案 B

## 1. 体验目标

用户不需要相信 AI，而是能够看懂并控制 AI 如何把一句话变成规则。界面围绕三个问题组织：系统如何理解、规则如何执行、与上次相比发生了什么。

## 2. 信息架构

```text
策略工作台
  -> 输入投资假设
  -> Strategy Canvas：意图、代理指标、阈值来源、澄清项
  -> 确认并全量执行
  -> 结果总览：覆盖率与漏斗
       -> 候选
       -> 临界未入选
       -> 数据缺口与异常
       -> Evidence
  -> 保存策略
  -> 已保存策略：重跑、版本、变化摘要
```

## 3. 页面与用户任务

| 页面 | 用户要回答的问题 | 核心组件 | 主动作 |
| --- | --- | --- | --- |
| 策略输入 | 我想验证什么判断？ | 输入区、示例、合规边界 | 构建策略 |
| Strategy Canvas | 系统如何理解我的话？ | 意图行、代理选择、阈值来源、公式提示 | 选择、编辑、删除、确认 |
| 执行进度 | 是否真的覆盖完整股票池？ | 成分、估值、财务、价格四阶段进度和覆盖率 | 等待、重试 |
| 结果总览 | 哪些符合，哪些接近，哪些无法判断？ | 可对账漏斗、状态 Tabs、最强约束 | 切换状态、展开标的 |
| Evidence | 这个结论来自哪里？ | 原值、计算值、公式、来源、时点、request_id | 复制引用、关闭 |
| 保存策略 | 我以后如何继续验证？ | 策略名称、当前版本、重跑频率 | 保存、稍后处理 |
| 已保存策略 | 相比上次有什么变化？ | Execution 时间线、变化摘要、版本 diff | 重跑、修改、查看变化 |

## 4. Strategy Canvas

每个用户表达占一行，固定展示五列：

```text
用户原话 | 投资意图 | 代理指标 | 阈值与来源 | 状态
```

示例：

```text
估值合理 | 相对估值不高 | PE-TTM 股票池分位 | 后 40%，来源：股票池分布 | 待确认
```

交互要求：

- 代理指标使用单选菜单，不用自由文本让用户猜字段名；
- 相对分位和绝对阈值使用分段控制；
- 建议值旁明确显示“模板建议”或“基于本次股票池”；
- 可展开“为什么使用这个指标”，但不在主界面堆积方法论文本；
- 所有阻断项解决前，“确认并执行”禁用，并显示具体原因；
- 批量澄清集中在一个页面完成，不连续弹出聊天问题。

## 5. 全量执行进度

执行区固定显示：

```text
股票池 300/300
估值 300/300
财务 287/300，13 个数据缺口
价格 296/300，4 个工具错误
最终归类 300/300
```

超过 10 秒时每 5 秒更新一次进度。任何阶段数量无法对账时停止发布结果并显示 `DATA_ERROR`。样本验证模式必须使用明显标题“策略样本验证”，不能只在辅助文字中解释。

## 6. 结果结构

结果页首先显示覆盖率，然后使用 Tabs：

- 候选；
- 临界未入选；
- 其他未通过；
- 数据缺口；
- 工具错误。

“临界未入选”定义为仅一个必填条件 FAIL，它比简单展示候选更能帮助用户理解策略敏感度。默认不做综合评分或排名，排序只允许按用户选定事实字段。

每行必须显示条件矩阵。未出现在当前 Tab 的股票仍能通过搜索定位其状态，不能从 UI 中消失。

## 7. 保存与变化

结果完成后的主按钮不是“继续研究”，而是“保存此策略”。保存后显示：

- 策略名称和版本；
- 已确认条件摘要；
- 本次数据时点和覆盖率；
- 一键重新运行；
- P1 的每日/每周运行频率。

重跑后的变化摘要分为：

- 新增符合；
- 退出候选；
- 从 UNKNOWN 恢复；
- 新增数据缺口；
- 工具或时效状态变化。

每项变化必须能展开新旧 Evidence。产品只描述状态变化，不归因为利好、利空或投资机会。

## 8. Patch 设计

用户输入“PE 改成 20”后显示：

```text
修改：估值代理从“沪深300 PE 分位后40%”改为“PE-TTM < 20x”
阈值来源：UNIVERSE_PERCENTILE -> USER_EXPLICIT
保持不变：经营改善、走势稳定、股票池
影响：需要重新执行估值条件与最终归类
```

确认后生成新版本；取消后原版本和已保存策略不变。若基础版本已经变化，显示 `CONFLICT` 并要求重新生成 Patch。

## 9. 空、加载与异常

| 状态 | 页面表现 | 用户下一步 |
| --- | --- | --- |
| 未澄清 | 高亮缺少代理或阈值来源的行 | 完成选择 |
| 执行中 | 分阶段数量和覆盖率 | 等待或取消 |
| 零候选 | 保留完整漏斗，显示最强约束和临界未入选 | 修改策略，不自动放宽 |
| 数据缺口 | 独立 Tab，显示缺失字段和时点 | 查看 Evidence |
| Tool Error | 独立 Tab 和重试入口 | 重试或稍后重跑 |
| Stale | 显示实际 as_of 和新鲜度规则 | 更新快照 |
| 覆盖不足 | 阻断正式候选，切换样本验证模式 | 补齐数据 |

## 10. 视觉与文案

- 采用安静、信息密集的研究工作台风格；不用聊天气泡主导流程。
- 状态颜色必须同时配合文本：PASS 绿色、FAIL 红色、UNKNOWN 金色、TOOL_ERROR 橙红、STALE 紫灰。
- 不显示“AI 推荐”“优质股票”“买入机会”等文案。
- “系统建议”必须紧邻建议来源；“用户已确认”使用不同状态。
- 当前实现使用 300/300 版本化 Snapshot，顶部显示“真实数据 · 全量快照”；若未来快照不完整，必须自动降级为“样本验证”且不能显示完整筛选。
