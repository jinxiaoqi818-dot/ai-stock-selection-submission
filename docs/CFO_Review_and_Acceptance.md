# CFO 审查与量化验收标准

## 1. 投资结论

结论：**批准预算受限的 MVP 验证，不批准规模化投入。**

本项目的合理投资命题不是“AI 会选出更好的股票”，而是验证一个更窄的效率与可信度命题：目标用户能否更快地将自然语言转为可执行规则，并能否核验每条结果的来源和规则。产品不提供收益预测，因此不能以投资回报率或荐股胜率作为商业价值证明。

本阶段的投入上限为 **40 人工小时、50 次真实数据试运行、单次成功执行的可变成本不高于人民币 2.00 元**。只有全部量化验收门槛通过，才进入下一阶段的产品化预算评审。

## 2. 为什么可能值得投入

| 投资假设 | 可验证价值 | 量化证明方式 | 通过门槛 |
| --- | --- | --- | --- |
| 用户难以把研究想法变成规则 | 降低策略配置时间 | 目标用户完成指定任务的端到端时长 | 20 名目标用户中，至少 14 名独立完成；中位时长不超过 5 分钟 |
| 用户不信任黑箱筛选 | 证据追溯降低核验成本 | 随机抽样执行结果的 Evidence 完整性 | 抽取 100 条条件判断，100 条均能查到值、阈值、来源、时点、单位和口径 |
| 自然语言修改优于重建条件 | 降低迭代操作量 | 指定 Patch 场景的字段变更正确率 | 50 次“PE 改为 20，其他不变”中，50 次只改目标字段 |
| 真实工具可支撑主链路 | 形成可运营能力 | 真实数据执行成功率与性能 | 连续 50 次已确认策略执行中，至少 47 次成功返回结果；P95 端到端耗时不超过 60 秒 |

这些是验证“是否继续投入”的指标，不是已被当前 Demo 证明的结论。

## 3. 当前证据不足

| 结论或假设 | 当前证据 | 缺口 | 需要补充的可接受证据 |
| --- | --- | --- | --- |
| 目标用户愿意使用 | 只有用户画像和逻辑推演 | 没有访谈、任务观察或留存数据 | 20 名符合画像用户的可回放测试记录和问卷原始结果 |
| 产品节省时间 | 没有人工筛选对照数据 | 无基线，不能证明“降低成本” | 同一任务的人工流程与产品流程时长，按同一用户和同一策略比较 |
| 扶摇可完成 P0 筛选 | 文档能力描述 | 未验证真实 Tool Contract、覆盖率、限频、SLA | 50 次真实调用日志、请求参数、字段映射、错误率和数据时点 |
| iFinD 能形成研究增量 | 公开能力介绍 | 未证明调用可用、授权允许、内容可追溯 | 一次真实研究调用及包含来源 ID、发布时间、原文链接的 Evidence |
| 经济性成立 | 没有供应商报价、Token 用量、基础设施成本 | 单位成本未知 | 50 次执行的成本明细和每次成功执行的 P50/P95 成本 |
| 可扩张 | 没有并发、失败恢复、支持成本数据 | 无法估计运营成本 | 10 并发压测、失败重试日志和人工介入工时 |

## 4. 成本收益审查

当前方案没有价格、付费转化、留存、获客成本或数据授权成本，**不能计算收入、毛利或投资回收期**。因此不应在汇报中宣称商业收益或 ROI。

MVP 阶段仅核算单位经济性：

```text
单次成功执行可变成本 = LLM 调用成本 + 扶摇调用成本 + iFinD 调用成本 + 计算与存储成本
```

验收时以服务端日志按 `execution_id` 汇总，分母只取 `RESULT_READY` 的执行：

```text
P95 单次成功执行可变成本 <= RMB 2.00
总开发投入 <= 40 人工小时
真实工具试运行次数 = 50
```

若任一供应商价格、授权范围或成功执行成本无法在上述上限内确认，项目停止在 Demo 阶段，不进入推广或规模化研发。

## 5. 原方案中不可验收或模糊的表述

| 原表述 | 为什么不能验收 | 替换后的验收表达 |
| --- | --- | --- |
| 降低策略配置成本 | 无基线、无样本、无时间窗口 | 20 名目标用户完成指定策略的中位时长 <= 5 分钟；成功数 >= 14 |
| 每个条件有 Evidence | 未规定 Evidence 字段、样本和覆盖率 | 100 条随机条件判断的 11 个必填字段完整率 100% |
| 完整主流程可操作 | “完整”和“可操作”没有判定方法 | T01-T07 全部通过，且 20 名用户中至少 14 名无需研究员帮助完成 |
| 实际 Tool Contract 测试通过 | 未规定调用次数、成功率和性能 | 50 次真实执行成功数 >= 47，P95 <= 60 秒；每次保留 request_id |
| 单元测试覆盖边界 | 没有覆盖率和边界清单 | CAGR、波动率、null、0/负基数、少于 60 个交易日、单位冲突各至少 1 个自动化用例，语句覆盖率 >= 80% |
| 不正常化异常 | 未定义异常比例和断言 | 对 10 个异常用例，10 个均不得产出 PASS/FAIL 正常结论 |
| 提高信任 | 主观且无可观察指标 | Evidence 完整率 100%；20 名测试用户中至少 16 名能在 60 秒内定位指定结果的来源与时点 |

## 6. 最终验收标准

以下条件必须**全部**满足；任一条件失败，状态为 `NOT_ACCEPTED`。

| 编号 | 验收对象 | 可量化标准 | 证据 |
| --- | --- | --- | --- |
| A01 | 可访问性 | 公网 URL 在 3 个独立网络请求中均返回 HTTP 200；首次内容渲染 <= 3 秒 | 部署日志与访问记录 |
| A02 | 主链路 | 20 名目标用户中至少 14 名，在无人工提示下完成“输入 -> 确认 -> 结果 -> 证据 -> 选择两只候选对比 -> PE 修改 -> v2” | 屏幕录制或埋点事件 |
| A03 | 效率 | A02 成功用户的端到端时长中位数 <= 5 分钟 | 时间戳事件表 |
| A04 | 解析正确性 | 50 条预先标注输入中，Intent、Universe、三项 P0 条件的全字段完全匹配次数 >= 45 | 固定 Eval 集与比对结果 |
| A05 | Patch 正确性 | 50 条预先标注 Patch 中，JSON Patch 完全匹配次数 = 50；未确认 Patch 的状态写入次数 = 0 | Patch 日志与差异检查 |
| A06 | 工具可靠性 | 50 次真实的确认后策略执行中，`RESULT_READY` >= 47；P95 时长 <= 60 秒 | execution 日志、request_id |
| A07 | 数据可追溯 | 随机抽取 100 条 PASS/FAIL/UNKNOWN 条件判断，Evidence 的 11 个必填字段完整率 = 100% | Evidence 导出与审计脚本 |
| A08 | 异常处理 | 缺失、过期、冲突、超时、5xx、限频、空股票池、少样本、非法参数、部分标的失败共 10 个用例全部通过；异常结果被标记为正常 PASS/FAIL 的次数 = 0 | 自动化测试报告 |
| A09 | 合规 | 100 条红队提示中，预测、收益承诺、直接买卖建议输出次数 = 0；仓库 secrets 扫描命中真实密钥次数 = 0 | Eval 输出与扫描报告 |
| A10 | 单位成本 | 50 次真实执行中，P95 单次成功执行可变成本 <= RMB 2.00；开发投入 <= 40 人工小时 | 供应商账单、Token/调用日志、工时记录 |
| A11 | iFinD 范围 | 若声明已接入 iFinD：至少 1 个真实研究调用，100% 返回来源 ID、发布时间、原文链接或不可访问原因；若未接入：UI 不出现“实时 iFinD 研究”字样 | 调用日志或产品截图 |
| A12 | 版本与审计 | 抽取 20 个已执行策略版本，20 个均可关联 `strategy_id`、version、确认时间、执行 ID、as_of 与参数哈希 | 审计导出 |
| A13 | 研究交接 | 20 名测试用户中至少 16 名能在 60 秒内从候选对比页指出 1 个数据差异或缺失项，并选择对应的事实型研究问题；不可比字段被展示为正常比较的次数 = 0 | 屏幕录制、埋点与对比日志 |

## 7. 预算闸门

- 仅当 A01-A09 全部通过，才允许使用不超过 40 人工小时完成真实数据 Pilot。
- 仅当 A01-A13 全部通过，才允许申请下一阶段产品化预算。
- 不满足 A06、A07、A08、A09 或 A10 中任一项，停止扩大用户规模；先修复数据、合规或单位经济性问题。
