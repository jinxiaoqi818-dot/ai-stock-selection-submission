# 业务负责人复核与方案 B

## 1. 候选人的产品判断

在完成第一版方案与真实数据验证后，候选人对产品进行了第二轮审查。结论是：第一版在工程可信、异常治理和证据追溯上较完整，但仍存在三个会削弱产品价值的结构性问题。

1. **主承诺大于实际覆盖。** 产品说“筛选沪深 300”，但有限样本执行不能解释其余标的为何未入选。未评估、数据缺失和条件不满足必须严格区分。
2. **模糊意图被过早翻译成固定阈值。** “经营改善、估值合理、走势稳定”不是单一指标；10%、25x、30%只能是代理规则建议，不能替代用户澄清。
3. **用户任务停在一次性结果。** 只展示候选和证据不足以形成持续价值；用户需要保存已确认策略、重新执行并识别状态变化。

以上判断由候选人审定并作为最终产品方案的依据。AI 编码工具用于辅助审查、整理表达和实现验证，不替代候选人的产品取舍。

## 2. 方案 B 定位

产品定位调整为：**AI 投资假设编译与监控工作台**。

它面向每周至少进行一次 A 股复盘、已经形成模糊研究判断但不熟悉量化配置的自主投资者，帮助其把一句投资假设转化为：

- 可检查的意图拆解；
- 可选择的代理指标；
- 可确认的执行规则；
- 覆盖完整股票池的筛选结果；
- 可追溯的入选、临界未入选和数据缺口；
- 可保存、重跑并观察变化的策略版本。

产品不评价策略是否能取得收益，不给出排名、预测或买卖建议。核心价值是降低“从想法到可验证规则”的成本，并使同一判断可以持续复查。

## 3. 目标用户与核心任务

### 3.1 目标用户

首要用户不是完全不了解金融指标的新手，也不是已有成熟量化平台的专业机构，而是：

- 具备基本财务和估值常识；
- 经常用“改善、合理、稳定”等语言记录选股想法；
- 会使用行情软件，但不愿反复配置复杂条件；
- 需要知道规则为何命中，以及本周相对上周发生了什么变化。

### 3.2 Job to Be Done

> 当我形成一个模糊的选股判断时，我希望快速把它变成自己理解并确认过的规则，在完整股票池中执行，保存下来并在未来复查变化，而不是直接相信一个黑箱推荐名单。

### 3.3 核心成功信号

北极星指标：**从自然语言输入到保存有效策略的完成率**。

护栏指标：全股票池覆盖率、澄清完成率、Evidence 完整率、异常正常化次数、策略再次运行率。

## 4. 产品原则

1. **先解释含义，再讨论阈值。** 模糊概念先拆解为投资意图和代理指标，不直接填默认数字。
2. **建议必须说明来源。** 阈值标注为用户输入、模板建议、股票池分位数或历史版本，不得混用。
3. **全量比多指标更重要。** 在资源受限时，优先对完整股票池执行较少条件，不用少量样本冒充全量候选。
4. **结果不仅有入选和排除。** 至少区分候选、临界未入选、数据缺口、异常和未评估；正式筛选不得存在未披露的未评估标的。
5. **一次策略应可以复用。** 已确认规则必须能保存、重跑和比较版本差异。
6. **AI 不拥有金融事实和最终判断。** AI提出映射候选；用户确认规则；金融工具提供事实；确定性引擎计算结果。

## 5. 策略澄清设计

用户输入“经营改善、估值合理、走势稳定”后，系统不直接生成 10%、25x、30%，而是展示一个策略画布：

| 用户表达 | 投资意图 | P0 代理指标候选 | 建议方式 |
| --- | --- | --- | --- |
| 经营改善 | 盈利趋势正在变好 | 最近年度利润增长为正；两年利润 CAGR 为正 | 默认选择组合规则，允许用户切换 |
| 估值合理 | 相对股票池不处于高估区间 | 正 PE-TTM 且处于沪深 300 较低分位；或用户输入绝对上限 | 默认使用股票池分位数，显示样本分布 |
| 走势稳定 | 相对股票池波动较低 | 60 日年化波动率处于沪深 300 较低分位 | 默认使用股票池分位数，允许绝对阈值 |

批量澄清只问影响执行的高价值问题：

1. “经营改善”更关注持续增长，还是亏损转盈？
2. “估值合理”按股票池相对位置，还是绝对 PE 上限？
3. “走势稳定”按相对低波动，还是你指定的波动率？

每一项必须显示代理指标、公式、建议来源和待确认状态。所有阻断项解决前，执行按钮保持禁用。

## 6. 方案 B 核心流程

```text
输入投资假设
  -> 拆解意图与不确定项
  -> 选择代理指标和阈值依据
  -> 确认 Strategy State
  -> 对完整沪深 300 执行分阶段筛选
  -> 查看候选、临界未入选、数据缺口和异常
  -> 展开 Evidence 核验
  -> 保存策略并命名
  -> 手动或定期重新执行
  -> 查看新增符合、退出候选和数据状态变化
```

## 7. 结果信息架构

结果页默认回答五个问题：

1. 实际评估了多少只，覆盖率是否为 100%；
2. 哪些股票满足全部已确认条件；
3. 哪些股票只差一个条件，以及差在哪；
4. 哪些股票因为缺失、过期或工具失败无法判断；
5. 相比上次运行，哪些状态发生了变化。

正式候选漏斗的每一个数字都来自真实执行。若受运行环境限制只能评估样本，页面必须切换为“策略样本验证”模式，不能展示成全量选股结果。

## 8. P0/P1 重新排序

| 优先级 | 范围 | 原因 |
| --- | --- | --- |
| P0 | 全沪深 300 覆盖、真实 Evidence、覆盖率展示 | 候选结果成立的前提 |
| P0 | 代理指标选择、阈值来源和阻断式澄清 | 防止系统替用户做金融判断 |
| P0 | 候选、临界未入选、数据缺口 | 直接支持用户核验策略 |
| P0 | 保存策略、版本和一键重跑 | 形成最低可持续使用闭环 |
| P1 | 定期监控和变化通知 | 在保存与重跑验证后扩展 |
| P1 | 行业相对估值、更多经营改善指标 | 依赖行业分类和更完整数据 |
| P1 | iFinD 资讯研究、回测 | 不影响 P0 价值证明，后置 |

## 9. 阶段闸门

| 阶段 | 通过条件 | 停止条件 |
| --- | --- | --- |
| G0 全量数据闭环 | 沪深 300 覆盖率 100%，每只均落入候选、未通过、数据缺口或异常之一 | 存在未披露的未评估标的，或漏斗无法对账 |
| G1 策略语义 | 预标注输入中，代理指标和澄清项与人工标准一致 | 模糊词被静默转为确认阈值 |
| G2 使用闭环 | 用户能完成表达、澄清、全量执行、核验证据和保存策略 | 用户不能解释规则含义或结果来源 |
| G3 持续价值 | 已保存策略产生再次运行和可理解的变化记录 | 用户只使用一次，或变化无法回溯 Evidence |

## 10. 明确不做

- 不用部分股票的结果代表沪深 300 全量候选。
- 不把固定阈值包装成 AI 对“合理”或“稳定”的正确理解。
- 不用多 Agent 数量证明 AI 能力，逻辑职责可以由一个受约束的模型调用完成。
- 不在全量覆盖和策略语义通过前扩展 iFinD、回测、资讯摘要或复杂视觉功能。
- 不把筛选命中率、收藏数或候选收益当作当前产品有效性的证明。
