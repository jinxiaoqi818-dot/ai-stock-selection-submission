# 第十部分 PRD：方案 B

## 1. 产品定义

产品名称：AI 投资假设编译与监控工作台。

首要用户：每周进行 A 股复盘、具备基础金融常识、能描述判断但不擅长把判断配置成量化规则的自主投资者。

核心任务：把模糊投资假设转成用户理解并确认过的代理指标，在完整股票池中执行，并将策略保存为可以再次运行和检查变化的版本。

产品输出是“已确认规则与真实数据的匹配状态”，不是股票推荐。任何结论都必须展示来源、时点、字段、单位、统计口径和质量状态。

## 2. 用户问题与价值假设

用户的困难不是不会说出“经营改善、估值合理、走势稳定”，而是：

1. 不知道模糊概念可以由哪些指标代理；
2. 不知道系统是否正确理解了自己的判断；
3. 传统筛选器配置复杂，修改后难以回忆变化；
4. 一次性候选名单无法持续验证同一投资假设。

价值假设：如果产品能够清楚展示“表达 -> 代理指标 -> 阈值依据 -> 全量结果 -> 证据 -> 再次运行”的完整链路，用户会更快形成可执行策略，并更愿意保存和复查，而不是盲信黑箱候选。

北极星指标：**自然语言输入后成功保存有效策略的会话占比**。

## 3. 目标与范围

| 类型 | 内容 | 验收标准 |
| --- | --- | --- |
| 产品目标 | 降低从投资假设到可执行规则的配置成本 | 目标用户能解释每个代理指标，并完成确认和保存 |
| 产品目标 | 保证候选结果真实完整 | 股票池覆盖率 100%；候选、未通过、数据缺口和异常数量可对账 |
| 产品目标 | 支持持续复查 | 已保存策略可再次执行，并展示相对上次运行的状态变化 |
| P0 范围 | 沪深 300、意图拆解、代理指标选择、全量执行、Evidence、临界未入选、保存与重跑 | 不存在未披露的未评估标的；保存版本不可原地覆盖 |
| P1 范围 | 定期监控、变化通知、行业相对估值、iFinD 研究增强 | P0 全量闭环和用户任务验证通过后接入 |
| 非目标 | 下单、荐股、收益预测、全量回测平台 | UI 和 AI 均不得暗示上述能力 |

## 4. 核心对象

### 4.1 Intent Map

Intent Map 保留用户原话，并把每个模糊概念拆为：投资意图、代理指标候选、仍需回答的问题。它不能包含未经确认的执行阈值。

### 4.2 Strategy State

Strategy State 是唯一可执行的策略版本，至少包含 `strategy_id`、`version`、`universe`、`conditions`、`threshold_source`、`as_of`、`status` 和审计信息。只有所有阻断澄清项都解决并由用户确认的版本才能执行。

### 4.3 Evidence

Evidence 绑定“规则判断”和“原始事实”。每条记录包含 `metric`、`provider_field`、`raw_value`、`computed_value`、`operator`、`threshold`、`threshold_source`、`result`、`source`、`request_id`、`as_of`、`period`、`unit`、`formula` 和 `quality_status`。

### 4.4 Saved Strategy 与 Execution

Saved Strategy 指向不可变的已确认版本。每次运行创建新的 `execution_id`，保留覆盖率、漏斗、数据时点和 Evidence。新旧 Execution 可以计算状态变化，但不得改写历史结果。

## 5. 主流程

| 步骤 | 用户动作 | 系统动作 | 可见产物 | 退出条件 |
| --- | --- | --- | --- | --- |
| 1 表达 | 输入自然语言 | 提取股票池、投资意图和模糊项 | 原始表达、Intent Map | 输入非空且合规 |
| 2 选择代理 | 选择指标口径 | 展示可执行代理、公式和数据要求 | Strategy Canvas | 每个意图有唯一代理 |
| 3 确认阈值 | 选择相对分位或绝对值 | 标记阈值来源，检查冲突 | Draft Strategy | 无阻断澄清项 |
| 4 确认 | 点击确认 | 锁定版本、参数与哈希 | Confirmed Strategy | 用户明确确认 |
| 5 全量执行 | 等待或重试 | 对完整股票池分阶段筛选 | 覆盖率、漏斗、状态矩阵 | 数量可对账或整体失败 |
| 6 核验 | 查看候选、临界未入选和缺口 | 输出受 Evidence 约束的原因 | Evidence Drawer | 用户完成核验 |
| 7 保存 | 命名并保存策略 | 记录版本和本次执行 | Saved Strategy | 保存成功 |
| 8 重跑 | 手动或按计划重跑 | 创建新 Execution 并比较状态 | 新增符合、退出候选、质量变化 | 新运行结束 |
| 9 修改 | 输入自然语言修改 | 生成最小 Patch 和影响范围 | Patch Preview | 用户确认或取消 |

## 6. 策略语义与澄清

### 6.1 代理指标原则

模糊概念不等于固定指标。系统必须先给出代理选择，再提供阈值建议。

| 用户意图 | P0 推荐代理 | 替代选项 | 默认阈值依据 |
| --- | --- | --- | --- |
| 经营改善 | 最近年度利润增长为正，且两年归母净利润 CAGR 为正 | 用户指定 CAGR 下限；亏损转盈 | 规则模板，不声称唯一正确 |
| 估值合理 | 正 PE-TTM 位于沪深 300 较低 40% | 用户指定绝对 PE 上限 | 本次有效股票池分布 |
| 走势稳定 | 60 日年化波动率位于沪深 300 较低 40% | 用户指定绝对波动率上限 | 本次有效股票池分布 |

行业相对 PE 需要稳定的行业分类和同行样本，作为 P1，不能在 P0 无数据支持时声称已实现。

### 6.2 阈值来源

每个条件的 `threshold_source` 只能是：

- `USER_EXPLICIT`：用户原话明确给出；
- `UNIVERSE_PERCENTILE`：根据本次有效股票池分布计算；
- `TEMPLATE_PROPOSED`：模板建议，必须等待确认；
- `PRIOR_VERSION`：沿用上一已确认版本。

系统不得把 `TEMPLATE_PROPOSED` 静默变为已确认条件。

### 6.3 澄清策略

- 一次批量展示所有高影响问题，避免聊天式逐题追问。
- 只询问会改变执行结果的问题，不要求用户理解供应商字段。
- 每个选项显示含义、公式、数据可用性和结果可能变化。
- 未解决的实体、代理指标、阈值来源或冲突都会禁用执行按钮。

## 7. 结果设计

结果必须把完整股票池划分为互斥集合：

1. `CANDIDATE`：所有必填条件为 PASS；
2. `NEAR_MISS`：仅一个必填条件为 FAIL，便于理解最强约束；
3. `NOT_MATCHED`：两个及以上条件为 FAIL；
4. `DATA_GAP`：至少一个条件为 UNKNOWN 或 STALE，且无工具级失败；
5. `TOOL_ERROR`：至少一个核心数据调用失败；
6. `NOT_EVALUATED`：只允许出现在明确标识的样本验证模式，正式筛选中数量必须为 0。

漏斗顶部必须展示 `evaluated_count / universe_total` 和覆盖率。不存在“没有出现在表格里但用户不知道原因”的股票。

## 8. 功能需求

| ID | 功能 | 需求 | 验收 |
| --- | --- | --- | --- |
| F01 | 策略输入 | 保留用户原话，支持示例和合规拒绝 | 原始表达可回看 |
| F02 | 意图拆解 | 显示投资意图、代理指标候选和歧义 | 不静默替用户选择指标 |
| F03 | Strategy Canvas | 条件可选择、编辑、删除，并显示阈值来源 | 阻断项未解决时不可执行 |
| F04 | 全量筛选 | 覆盖完整沪深 300，并显示覆盖率 | 所有标的状态可对账 |
| F05 | 结果解释 | 展示候选、临界未入选、缺口和 Evidence | 每项状态都可回到原始字段 |
| F06 | 保存与重跑 | 保存已确认版本并创建新的 Execution | 历史执行不可被覆盖 |
| F07 | 变化摘要 | 对比两次执行的新增符合、退出候选和质量变化 | 每个变化关联两次 Evidence |
| F08 | 自然语言修改 | 输出最小 JSON Patch、保留项和影响范围 | 未确认 Patch 不改变当前版本 |
| F09 | 候选对比 | 最多比较 3 只，同口径才展示数值 | 不可比项标为 `NOT_COMPARABLE` |
| F10 | 异常呈现 | 区分缺失、过期、冲突、数据错误和工具错误 | 异常不得转换为正常 PASS/FAIL |

## 9. AI、引擎与数据职责

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| AI 理解层 | 意图拆解、代理指标候选、澄清问题、Patch 候选、受证据约束的语言说明 | 生成金融事实、直接确认阈值、决定 PASS/FAIL |
| Schema Validator | 校验实体、指标、单位、阈值来源和 Patch | 理解自然语言 |
| 金融数据工具 | 返回指数成分、财务、估值和行情事实 | 解释用户意图、作投资判断 |
| 确定性引擎 | 计算指标、分位数、规则状态、覆盖率和版本差异 | 改写用户策略、补造缺失数据 |
| 用户 | 选择代理指标、确认阈值和策略版本 | 处理底层字段映射和工具错误细节 |

逻辑职责可以由一个受约束的模型调用完成，不以部署多个 Agent 作为产品目标。

## 10. 验收分层

### 10.1 24 小时提交验收

1. 公网 URL、源码、README、AI 使用记录和测试说明齐全。
2. 至少一条真实数据主链路可追溯到 `request_id`。
3. 模糊表达能够展示代理指标和待确认项。
4. 异常不会被伪装成正常 PASS/FAIL。
5. 当前未实现的全量覆盖、保存或监控能力必须明确标记，不以方案文档替代产品事实。

### 10.2 Pilot 验收

1. 全股票池覆盖率 100%，漏斗与状态集合可对账。
2. 预标注输入中，意图、代理指标和澄清项全字段正确率达到 90%。
3. 目标用户能够解释规则含义并完成保存策略。
4. 保存策略产生真实再次运行记录，变化均可关联 Evidence。
5. 详细可靠性、成本、合规和用户任务门槛见 `CFO_Review_and_Acceptance.md`。

## 11. 当前实现边界

当前 Web 产品已经验证真实扶摇字段、确定性计算、Evidence、Patch 和异常状态，并通过受保护的分块构建流程生成 300/300 的版本化沪深 300 Snapshot。全量覆盖问题已解决；尚未实现 Strategy Canvas 的代理指标选择、服务端策略保存、再次运行历史和变化摘要。
